# 法典数据包

法典笔记把“读哪一部法典”和“怎样读、怎样记”分开：

- `demo/codes/<名称>/` 是一部法典的**数据包**：正文、目录层级、引用格式、条旨、使用说明的例题，以及这部法典专有的材料和功能。
- `demo/src/` 是各部法典**通用**的软件：阅读、笔记、关联、记忆卡片、搜索、导出与同步。

`python3 demo/build.py` 为每个数据包生成一个页面：`demo/data/content.json` 中 `codex` 指定的默认数据包（宪法）生成 `法典笔记.html`，其他数据包生成 `法典笔记-<名称>.html`。只生成一个时写 `FADIAN_CODEX=<名称> python3 demo/build.py`。

每部法典是一本独立的笔记：浏览器记录、本机服务的端口和数据文件夹、导出的文件名（如 `法典笔记数据-民法典.json`）都各自分开，笔记不会混在一起，宪法原有的记录名也不变。PC&Mac 通用版中，每个数据包有自己的启动文件（如「打开法典笔记-民法典.command」）；网页版中，宪法在网站根目录，其他法典在各自的子目录。

## 数据包里的文件

| 文件 | 内容 | 必需 |
| --- | --- | --- |
| `codex.json` | 法典名称、引用格式、目录层级、欢迎语、功能开关，并列出下面各文件 | 是 |
| `versions.json` | 各年正文：每一条（或序言的每一自然段）在各年份的条号和段落，以及相邻年份的增删 | 是 |
| `subtitles.json` | 每条的条旨，用户可以改写 | 是 |
| `guide.json` | 使用说明：研读六步、操作提示，例题引用本法典的条文 | 是 |
| `revision-history.json` | 修改的官方说明（宪法为修正案草案说明），逐段归到条文 | 否 |
| `english.json` | 官方英文译本 | 否 |
| `review-history.json` | 宪法专有：备案审查工作报告和审查案例中援引条文的段落 | 否 |
| `build_*.py` | 生成上述数据的维护工具，写明来源和核对方法 | 建议 |

`codex.json` 的 `files` 列出数据包有哪些文件，页面据此装入；没有列出的功能自动隐藏。例如只有一个版本的法典，没有 `revision-history.json`，修正对照里就只有当年文本。

## 目录层级：`levels` 和 `structure`

法典的结构各不相同。宪法有序言、章、节；民法典有编、分编、章、节；刑法有编、章、节，分则各章下又有节。数据包不套用统一模板，而是自己声明：

```json
"levels": {
  "part":    {"name": "编", "numbered": true},
  "subpart": {"name": "分编", "numbered": true},
  "chapter": {"name": "章", "numbered": true},
  "section": {"name": "节", "numbered": true},
  "plain":   {"name": "", "numbered": false}
},
"structure": [
  {"id": "general", "level": "part", "name": "总则", "from": "a1", "to": "a204", "children": [
    {"id": "g1", "level": "chapter", "name": "基本规定", "from": "a1", "to": "a12"}
  ]},
  {"id": "supplementary", "level": "plain", "name": "附则", "from": "a1259", "to": "a1260"}
]
```

- 每个节点用 `from`、`to` 写明从哪一条到哪一条，可以无限嵌套。
- `numbered` 为真时，自动生成“第一编”“第三章”这样的序号，默认在同级之内编号。民法典的章在一编之内跨分编连续编号（物权编第二分编从第四章开始），这时给章这一层级写 `"numberWithin": "part"`。个别节点的序号或标题不合规律时，在节点上直接写 `number` 或 `title`。
- 某一年还没有的条文自动跳过；某个部分在某一年没有任何条文，就不显示。节点名称在不同年份不同时，用 `names` 按年份写明（宪法第四章即如此）。
- 目录按这一结构分层折叠，目录、体系阅读、复习范围和关联范围都由它生成。条文多的法典，目录上方的查找框可以按条号或条旨直接找到条文。

## 几部法律合为一部法典

“网络法典”这样把几部法律放在一起读的数据包，每部法律是一个顶层节点，并在节点上写 `law`：

```json
{"id": "pipl", "level": "law", "name": "个人信息保护法", "from": "pi1", "to": "pi74",
 "law": {"name": "中华人民共和国个人信息保护法", "short": "个人信息保护法", "aliases": ["个保法"],
         "citation": {"latest": "《中华人民共和国个人信息保护法》", "original": "《中华人民共和国个人信息保护法》（{year} 年）",
                      "amended": "《中华人民共和国个人信息保护法》（{year} 年修正）"}}}
```

- 条文的 `id` 要在整个数据包中唯一，可以加上各法的前缀，如 `cs1`、`ds1`、`pi1`；`label` 照常写“第一条”。
- 列表、目录和笔记中，条号前自动加上法律简称（“个人信息保护法第十条”）；引文用各法自己的名称。
- 搜索框输入“个人信息保护法第十条”“个保法10”可以直接找到。不写法律名称时，按正在阅读的那部法律理解条号。
- `versions.json` 的 `years` 是各法通过和修改的年份。某部法律在某一年还没有通过，它的条文在那一年写 `"exists": false`；它通过的那一年显示为“原文”，不算新增。各法在哪一年没有修改，引文就沿用它最近一次通过或修改的年份。
- 年份在下拉框中的显示可以用 `yearLabels` 写明，如 `{"2021": "2021 年（数据安全法、个人信息保护法通过后）"}`；需要逐年指定引文写法时，在 `citation` 中写 `byYear`。

## 其他设置

| 设置 | 作用 |
| --- | --- |
| `portOffset` | 本机服务端口：纯净版是 8766 加上这个数，各数据包不能相同（宪法为 0） |
| `webFolder` | 网页版中的子目录名，如 `civil-code`；默认用数据包名称 |
| `searchQuery` | 智能辅助“关注主题”的默认检索词 |
| `english.json` | 官方英文译本。`sources` 按年份写出处；几部法律合为一部时，可以写成 `"<法律节点 id>:<年份>"` 或 `"<法律节点 id>"` |

## 相关规范和材料：`relationCategories`

学民法、刑法，要结合司法解释、行政法规、规章、指导性案例和典型案例。数据包可以声明材料类别，每个类别在“关联阅读”中有自己的一页，可以关联到条文、章节或整部法典，笔记也会显示在相应条文下。宪法数据包声明了“比较阅读”和“备案审查”。刑法数据包可以这样写：

```json
"relationCategories": {
  "interpretation": {"name": "司法解释", "materialType": "司法解释",
    "fields": [["document", "文件名称"], ["number", "文号"], ["provision", "条款"], ["status", "效力", ["有效", "已修改", "已废止"]]]},
  "case": {"name": "指导性案例", "materialType": "案例",
    "fields": [["number", "案例编号"], ["court", "法院"], ["holding", "裁判要点"]]}
}
```

`fields` 中每一项是 `[字段, 名称]`，或 `[字段, 名称, [选项…]]`，第四项写 `"multi"` 表示可以多选。

## 新建一个数据包

正在编写、尚未完成的数据包，文件夹名以 `_` 开头（如 `_civil-code`），不会被生成页面，也不会进入分发版本。

通常请使用下文的 `新法典/` 入口。以下是手工维护数据包时的格式说明。

1. 参考 `codes/constitution/` 的结构，新建一个尚未使用的法典目录。
2. 改写 `codex.json`：`id`（如 `cn-criminal-law`，备份按它区分法典）、名称、引用格式、目录结构、欢迎语。把 `features` 中不适用的功能删去。
3. 生成 `versions.json`。正文请取自[国家法律法规数据库](https://flk.npc.gov.cn/)，逐条核对。只有一个版本时，`years` 只写一个年份。宪法的 `build_versions.py` 可以作为参考。
4. 写 `subtitles.json`：可以先全部留空，由自己在阅读中填写。不要复制商业出版物中的条旨。
5. 改写 `guide.json` 中的例题，使它们引用本法典的条文。
6. 运行 `python3 demo/codes/check_pack.py <名称>` 检查：条号与序号是否一致、目录是否恰好覆盖全部条文、例题和条旨是否指向已有条文、端口是否冲突，并按法律、编和年份列出条数，与官方文本核对。
7. 运行 `python3 demo/build.py`，打开 `demo/法典笔记-<名称>.html` 检查；要连本机服务时，运行 `python3 demo/launch.py --open --codex <名称>`。

这些步骤可以交给编程助手完成，先让它阅读根目录的 `AGENTS.md`。条文要由自己核对。

## 积木：每部法典独立，新的法典随时加入

每部法典是独立的：一门课一部法典，各有自己的页面和笔记本。一份文件（一部法律、一份政策、任何文字）可以做成一个**模块**，放在 `demo/modules/<标识>/`；法典在 `codex.json` 中用 `"modules": […]` 列出它由哪些模块拼成。网络法典就是三个模块：网络安全法、数据安全法、个人信息保护法。

**加一部新的法典**（例如刑法）：从国家法律法规数据库下载 Word 文件，然后

```
python3 demo/make_pack.py 刑法.docx --name 中华人民共和国刑法 --short 刑法 --id criminal-law --prefix xs --year 2023 --code
python3 demo/build.py
```

就多了一部独立的法典，根目录多了「打开刑法笔记.command」。

- 支持 Word（.docx）和文本（.txt、.md）。法律按“第×条”切分，编、章、节成为目录；没有条文的政策文件按“一、二、三、”切分；其他文字按自然段切分。
- `--prefix` 是条文标识前的字母（`xs1`、`xs2`……），各模块不能相同。不加 `--code` 时只生成模块。
- 工具不改动文字，但切分结果要由自己对照原件核对。这样生成的法典只有一个年份的文本；历次修正的对照需要另行制作。

通常采用这个入口：把文件放进项目文件夹的 `新法典/<简称>/`，运行 `python3 demo/add_code.py 新法典/<简称>`，或请 AI 编程助手按 `新法典/给助手的说明.md` 操作。上面的 `make_pack.py` 是只处理单份文本的底层工具。

- 多份完整文本须在文件名写明年份，或在 `说明.txt` 中逐项写 `文本 1997：文件名`。跨年条文按文字相似度对应，须人工复核。
- `条旨.json` 保存有官方依据的条旨，`_说明` 和 `_来源` 保存出处；程序照抄。罪名须有依据，不得自编。
- `拟定条旨.json` 保存经使用者同意的拟定概括，不能冒充罪名。当前程序在存在非空 `条旨.json` 时一并读取它；只有拟定条旨的情形尚未验证。
- `分段参考 1997：文件名` 只提供分段位置，不替换正文文字。
- 有最初文本、现行文本两份和修正案时，`add_code.py` 调用 `replay.py` 逐项重建中间年份，并与现行文本比较。先确认修正案完整，再看核对报告中的差异。

本版不提供合并、拆分法典的操作。各法典保持独立；条文暂时无法匹配的记录会随备份暂存，格式见 `demo/数据格式.md`。

拼装由 `demo/compose.py` 完成（`build.py` 会先调用它）：它写出法典的 `versions.json`、`subtitles.json`，以及 `codex.json` 中的 `levels`、`structure`、`yearLabels` 和 `accepts`。这几项不要手改；`codex.json` 的其他内容照常手写。

## 一本笔记、几部法典

现在一个页面装一部法典（可以由几部法律组成），不同法典的笔记分开保存，备份带有 `bookId`，不会合并到另一部法典。要关联另一部法典，在条文下使用“关联其他法典的条文”，填写目标条文和理由。电脑完整版可查看对方条文、笔记及反向关联。
