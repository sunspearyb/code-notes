## 提取与校验方法

`build_versions.py`从命令行接收原始文件路径，先校验SHA-256，再读取DOCX正文XML。仅删除段首段尾空白，以及从正文分离条号所需的空白。正文词语、标点、分款和分项保持原样。条文内的括号、书名号及原有空格不作统一替换。

`sourceParagraphs`是DOCX正文中从1开始的段落位置，空段也参与位置计数；它不是款号或页码。`sourceFile`对应上述源文件。每个版本的全文、条号顺序和目录范围均有程序检查。重复运行的JSON文件已经逐字节比对。

| 合编年份 | 网络安全法 | 数据安全法 | 个人信息保护法 | 共计 |
| --- | ---: | ---: | ---: | ---: |
| 2016 | 79 | 0 | 0 | 79 |
| 2021 | 79 | 55 | 74 | 208 |
| 2025 | 81 | 55 | 74 | 210 |

这些年份是合编快照。2021年快照含两部新法通过后的文本，网络安全法仍为2016年通过文本；2025年快照收录2025年修正文本，其修正决定自2026年1月1日起施行。日期已经国家法律法规数据库的现行文本、修正决定和公报核实。

修正决定共14项。转换程序把这14项逐项作用于2016年文本，并调整内部援引条号；重建的81条与2025年官方全文逐段逐字一致。第11项涉及原第68条与第69条第一项的合并，第12项合并原第64、66、70条。原第64、66条保留为`cs64-2016`、`cs66-2016`历史单元；最新版本为不存在，合并去向为`cs71`。因此全包有212个稳定单元，现行条文为210条。

原条号与现条号映射保存在`amendmentDecision.oldToNew`，分拆合并记录保存在`mergers`。修正决定出处使用《全国人大常委会公报》2025年第6号的印刷页码792—794页，对应下载PDF第1—3页。PDF校验值已在下载时核对；构建条文时使用DOCX，并不从公报双栏排版重新拼接条文。

修正后网络安全法第81条仍写“本法自2017年6月1日起施行”。这是官方重公布文本的原有表述；2025年修正决定的施行日期另为2026年1月1日，两者分别记录。

```sh
python3 demo/codes/cyber-law/build_versions.py \
  --cyber-2016 /path/to/cyber-2016.docx \
  --cyber-2025 /path/to/cyber-2025.docx \
  --data-2021 /path/to/data-2021.docx \
  --personal-2021 /path/to/personal-2021.docx \
  --amendment /path/to/cyber-amendment-2025.docx
```

## 待使用者确认的内容

2026年10月18日，按使用者“每条的小标题，请你根据条款内容草拟”的要求，将全部条旨草稿载入`subtitles.json`，供正文、目录和检索使用。条旨均依据本条内容独立拟定，为4—10字，未采用商业出版物的标题。`subtitles-draft.json`保留同一版初稿，未直接列入构建清单。欢迎页和使用说明注明草稿性质；使用者可逐条修改。

研读六步的六个例题均显式标为“例题草案，待使用者确认”。每项所用条文、问题设置和学理联系，见同目录[例题审阅稿](例题审阅稿.md)。未把草案写成个人笔记。

中文法律的通过、修正、施行日期及条数已完成来源核实。尚待确认的是条旨和例题的学术取舍。

## 本包检验

在项目根目录运行：

```sh
python3 demo/codes/check_pack.py cyber-law
node demo/codes/cyber-law/test_pack.cjs
python3 demo/build.py
```

`test_pack.cjs`调用现有共用模型，核对实际条文与全部版本差异能否复原、目录范围、引用、检索、英译条号、空初始笔记、草稿范围及跨法典备份隔离。测试依赖项目的`demo/src/`，本包本身不修改这些文件。
