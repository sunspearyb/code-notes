# 法典笔记的数据格式

笔记有两种导出格式，内容相同，用途不同：

- **JSON**（`法典笔记数据.json`，或“导出数据（JSON）”）：完整的数据，可以在任何一种版本中导入、合并，也是网盘同步使用的文件。迁移到其他软件时，以它为准。
- **Markdown**（`法典笔记.md`，或“导出笔记（Markdown）”）：给人和助手阅读，任何笔记软件都能打开。它不能导回法典笔记。

两种文件都是 UTF-8 编码的纯文本，不依赖本软件也能读。

## 笔记保存在哪里

| 打开方式 | 保存位置 | 怎样带到别处 |
| --- | --- | --- |
| PC&Mac 通用版，用启动文件打开 | 文件夹中的 `.fadian-clean-local/notebook.json`，并自动写出 `法典笔记数据.json`、`法典笔记.md` | 整个文件夹放进网盘即同步 |
| PC&Mac 通用版，直接用 Chrome 或 Edge 打开网页 | 浏览器中；在“导出同步”选择文件夹后，自动写出 `法典笔记数据.json`、`法典笔记.md` | 同上 |
| 网页版、Windows 版、安卓版 | 浏览器或应用中 | 导出 JSON |

## JSON 的主要内容

顶层是一个对象：

| 字段 | 内容 |
| --- | --- |
| `schemaVersion`、`notebookVersion` | 格式版本。新版本读取旧格式时自动迁移，不会丢弃字段 |
| `bookId` | 法典，如 `cn-constitution`。不同法典的备份不会互相合并 |
| `notes` | 条文笔记：`unitId`（条文）、`year`（文本年份）、`question`、`text`、`methods`（解释方法）、`anchors`（字句定位）、`history`（修改前的版本）、`createdAt`、`updatedAt`、`private`（为真时对助手隐藏） |
| `materialRelations` | 材料关联，包括比较阅读和备案审查：`scope`（关联范围）、`category`、`details`、`title`、`sourceText`、`text` |
| `materials` | 条文下的材料与依据 |
| `terms`、`links` | 词条；条文之间的关联 |
| `groups`、`groupLinks` | 自己划分的部分及其关系 |
| `marks` | 标记：`style`（`yellow`、`green`、`blue` 高亮，`underline`、`bold`）、`anchor`（某年文本中某一段的字句定位）。同一样式的标记互不重叠；合并备份时去掉完全相同的标记 |
| `subtitles`、`subtitleHistory` | 自己改写的条旨及曾用条旨 |
| `memoryCards` | 记忆卡片的关键词和复习安排 |
| `guideEdits`、`guideHistory` | 自己修改的使用说明 |
| `discussions`、`people` | 共享讨论的本地记录 |
| `deleted` | 删除记录：`id`、`kind`（记录种类，如 `notes`、`links`、`materials`、`groups`、`groupLinks`、`marks`）、`deletedAt`（删除时间）。用于合并时不把已删除的记录带回来，见“合并的规则” |
| `parked` | 暂存记录：`kind`、`record`，按键保存的记录另有 `key`。条文不存在或字句定位对不上时，记录暂存并随备份保留；原条文恢复后重新匹配 |
| `exportedAt`、`device` | 导出时间和设备，导入时忽略 |

### 条文怎样定位

`unitId` 是条文在数据包中的编号：宪法的序言各自然段为 `p1`—`p13`，各条按 2018 年条号为 `a1`—`a143`。条号在不同年份可能不同，所以笔记同时记下 `year`。字句定位 `anchor` 记录段落序号 `block`、起止字符位置 `start`、`end` 和原文 `quote`，导入时逐字核对，原文对不上就拒绝导入，不会把笔记挂到错误的字句上。

### 关联范围 `scope`

| `kind` | 含义 | 其他字段 |
| --- | --- | --- |
| `constitution` | 整部法典（名称沿用宪法时期） | `year` |
| `amendment` | 某一次修正 | `year` |
| `structure` | 一章、一节或一编 | `nodeId`、`year` |
| `group` | 自己划分的部分 | `groupId` |
| `articles` | 一条或几条 | `unitIds`、`year` |

## 合并的规则

导入、网盘同步和恢复备份都用同一个合并规则。

- 两边都有、内容相同的记录，只保留一份。
- 同一则笔记或同一条材料关联，两边内容不同时，采用修改时间较晚的一版；较早的一版不会丢，放进这则笔记的修改记录（`history`）里，可以在笔记的“修改记录”中查看。两边修改时间完全相同时，按固定顺序取其一，另一版同样进入修改记录。
- 同一个“自己划分的部分”两边不同时，采用修改时间较晚的一版。部分没有修改记录，较早的一版不保留。
- 词条、条文关联、材料等其他记录，内容不同时仍然两份都保留，由自己核对。
- 阅读位置（`current`、`year`）和阅读偏好（`preferences`）属于各台设备自己：已有记录的设备打开时保留自己的位置和偏好；只是翻页、切换年份或改偏好，不会重写网盘里的文件。

修改时间取自各台设备自己的时钟。设备时钟不准时，可能把较早的一版当作正文，另一版仍在修改记录里。

### 暂存记录怎样合并

条文暂时不在数据包内，或标注的原文字句对不上时，有关记录进入 `parked`，不丢弃。合并时汇集两边的暂存记录，完全相同的只留一份；后续读入数据时重新尝试匹配。当前没有启用合并或拆分法典的操作入口。

没有正文的草稿不会在合并时变成“从备份恢复的草稿”笔记。

### 删除怎样同步

删除笔记、条文关联、材料、部分、部分之间的关联和标记时，会在 `deleted` 中记下一条“已删除”。合并时，另一边还留着的同一则记录不再带回来。

- 如果另一台设备在删除之后又修改了这则记录，以修改为准，记录保留，这条“已删除”作废。
- 导入或恢复一份旧备份时，备份里已经被删除的记录同样不会回来。确实要找回，可以用文本编辑器打开备份文件查看。
- “清空此浏览器中的记录”不算删除，不会影响其他设备。
- 20261030-r4 及更早的版本不认识 `deleted`：它们能正常读取和合并新版写出的文件，但在这些旧版设备上，已删除的记录可能再出现，同一则笔记的两个版本也仍会并列保留。回到新版后再合并一次即恢复正常。

## 迁移到其他软件

- 只要文字：用 Markdown。Obsidian、Typora、Notion、印象笔记等都能导入。
- 要保留结构：读 JSON。字段名是英文，含义见上表；可以请编程助手写一个转换脚本。
