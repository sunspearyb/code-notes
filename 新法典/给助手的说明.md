# 给 AI 编程助手的说明：把一部新的法典加入法典笔记

使用者多为法学学生，不熟悉命令行。请你替他们完成操作，用平实的中文报告结果。

## 一、使用者会做什么

在 `新法典/` 下建一个文件夹（如 `新法典/刑法/`），放进：

- 现行文本一份：`.docx`、`.txt` 或 `.md`。有几份文件时，现行文本的文件名含“现行”二字。
- 历年文本（可选）：同一部法律各年的完整文本各一份，文件名里带四位年份（如 `立法法_2000年.md`、`立法法_2015年.md`、`立法法_2023年.md`）。有两份以上时，程序以年份最新的为现行文本，并自动做出各年文本和修正对照：相邻两个文本的条文按文字相似度对应，条号变了仍算同一条。
- 文件名里的年份不可靠时（例如文件夹里还有带年份的修正案），在 `说明.txt` 中逐个写明：`文本 1997：某文件.md`、`文本 2023：某文件.md`。
- 修正案、修改决定：直接放在文件夹或 `修正案/` 中。有两个以上年份的文本时，程序把每个修正案拆成各项，按“刑法第×条”“作为第×条之一”认出它修改的条文，在条文标题下显示标记（如“修三 2001”），并提供“历次修正案”一览。
- 只放了最初文本和现行文本两份、并放了全部修正案时，程序会从最初文本出发逐项重放修正案（`demo/replay.py`），得到每个修正年份的文本，并把最后结果与现行文本逐字比较；对不上的条文列在核对报告“逐项重放修正案”一节。最初文本的分段不可靠时（网页把几款连成一段），可以另放一份分段正确的文本，在 `说明.txt` 中写 `分段参考 1997：文件名`，程序只取它的分段，不取文字。
- 可选 `条旨.json`：有官方依据的条旨（如刑法的罪名），写成 `{"第一百二十条之一": "帮助恐怖活动罪", "_说明": "依据是什么"}`。程序只照抄，不生成。`"_来源": {"第×条": "文件名称和文号"}` 会成为条旨旁的“法定”标记。没有官方条旨的条文可以另写 `拟定条旨.json`（同样的格式），这些条旨不带标记，使用者可以修改；拟定时只概括条文内容，不得冒充罪名。
- 可选 `说明.txt`：`名称：`、`简称：`、`年份：`，每行一项（格式见 `新法典/_模板/说明.txt`）。还可以写 `标识：`（小写字母、数字、连字符，如 `criminal-law`）和 `前缀：`（1—8 个字母，如 `xs`，各法典不能相同）。
- 可选 `修正案/` 文件夹：历次修正案、修改决定的文本。

## 二、你要做的

1. 看一眼文件夹。没有 `说明.txt` 或没有填名称时，按文件内容补一份：名称用法律全称，年份用现行文本通过或最近一次修正的年份；建议同时写上便于辨认的 `标识` 和 `前缀`。`.doc` 或 PDF 请先转成 `.docx`，并提醒使用者核对文字。
2. 在项目根目录运行：

   ```
   python3 demo/add_code.py 新法典/刑法
   ```

   它会生成模块（`demo/modules/<标识>/`）、法典（`demo/codes/<标识>/`）、页面和「打开<简称>笔记.command」，并把 `核对报告.md` 写进该文件夹。只用 Python 标准库，不需要安装任何东西。
3. 读 `核对报告.md`。检查结果须为“检查通过”。把条数、各部分的起止与原件比较；发现不一致，先查原因（见第四节），不要手改生成的 JSON。
4. 向使用者报告：加入了什么、共多少条、怎样打开、还有哪些没有做（报告中已列出），并请他们对照原件核对。

要重做：`python3 demo/add_code.py 新法典/刑法 --redo`（删去上次生成的模块、法典、页面和启动文件，不删笔记）。

## 三、不要做的

- 不要自己编写条旨。刑法的罪名由最高人民法院、最高人民检察院《关于执行〈中华人民共和国刑法〉确定罪名的规定》及历次补充规定确定，只能按这些文件写入，并与官方文本核对；没有核对过的不要写入。

- 不要改动法律文字。程序只去掉段首段尾空白和条号后的分隔空白。
- 不要凭记忆补写或“修正”条文、条旨、修正案内容；缺什么就如实告诉使用者。
- 不要改 `demo/src/` 中的程序，不要动其他法典的文件夹和 运行时笔记文件夹。
- 不要重新打包各终端、上传 GitHub 或发布，除非使用者明确要求。

## 四、常见问题

- “条号不连续或重复”：原文件中多半有目录、题注，或正文段落以“第×条”开头。核对后在原文件副本中处理（例如删去重复的目录），再 `--redo`。
- “第×条之一”这类后来增加的条文可以识别，标识为 `<前缀>120-1`。
- 没有“第×条”的文件：按“一、二、三、”切分；都没有时按自然段切分。
- “前缀已被使用”：在 `说明.txt` 中另写一个 `前缀：`。
- 提示字体子集缺字：不影响使用，缺的字显示为系统宋体。
- 教师版应用：退出后重新打开，新法典出现在“法典”菜单中。

## 五、核对修正案与历史文本

有历年完整文本时，程序生成各年文本和逐字对照。核对报告中的“被删去或并入其他条的旧条文”要重点核对：改动很大的条文可能被当成“删去一条、新增一条”。修正案可按第一节挂到条文下；只提供最初文本和现行文本两份时会尝试重放。先检查是否收齐修正案、修改决定，再核对各年条数和最后文本。

核对报告末尾仍可能带有旧模板中的“没有修正案”提示，应结合“逐项重放修正案”部分及生成数据判断。如有矛盾，如实标出，不能据模板断言未处理。

- 重放差异必须逐条列给使用者，不能自行改动法律文字。数据格式见 `demo/codes/README.md`。
- 做完后运行 `python3 demo/codes/check_pack.py <标识>` 和 `python3 demo/build.py`。

## 六、相关文件

- `demo/add_code.py`：本说明所用的入口。`demo/make_pack.py`：切分文件。`demo/compose.py`：按模块拼装法典。
- `demo/codes/README.md`：数据包的格式。项目根目录的 `AGENTS.md`（公开版）：项目的总体约定。

本轮只按程序核对操作说明，未另取短法规执行加入流程；该流程尚未重新测试。若只有 `拟定条旨.json` 而没有非空 `条旨.json`，当前入口不会读取拟定条旨，不要向使用者声称已经收入。
